# Agent system audit: 2026-09-15

Scope: shared prompts, five workflows and profiles, four roles, five native adapters, launcher/UI, installation/rollback, task continuity, evaluation accounting, current model guidance, and release state. The audit used one lead, a separate self-review pass, three independent adversarial reviewers, and a fresh verifier. Reviewers used Astra 6 at high effort with fresh context. No comparative model benchmark ran.

## Findings and changes

| Priority | Finding | Resolution and evidence |
|---|---|---|
| High | Concurrent Codex launches rewrote the same worker role files, changing a running session's future worker settings. | Content-addressed immutable snapshots, atomic publication, parent symlink refusal, and concurrent regression coverage. |
| High | Installer rollback restored a preexisting file even after the user edited it. | Preserve modified originals and created files; preflight the whole rollback plan and recheck restores. Reproduced against the prior implementation. |
| High | Automatic recovery from an installation failure could overwrite, remove, or recreate a file changed after an earlier installation write. | Recheck installed bytes, modes, and symlinks, preserve concurrent content/permission edits, deletions, and symlink replacements, recover untouched writes atomically, and report the backup location without masking the original error. Fixed separately after the data-loss review reproduced the existing defect. |
| Medium | `preview` wrote role files, while `doctor` ignored the selected model, effort, worker settings, and target workspace. | Preview is read-only; doctor reuses launch configuration and reports the selected executable. CLI regressions and native Astra startup validated. |
| Medium | Shell PATH selected older Codex/Claude copies than those already installed. | Explicit `OAS_*_BIN` selection shared by launch, preview, UI discovery, and doctor; optional persistent selections in the installed wrapper. Invalid selections fail without fallback. |
| Medium | Cost reports mixed workflows and counted repeated passes of one task as separate completed tasks; NaN/Infinity were accepted. The first fix still combined distinct fields through an ambiguous display string. | Group by a tuple of workflow, cohort, harness, runtime, and model/effort fields; format labels separately. Count unique completed task IDs, charge every attempt, and reject non-finite telemetry. Old logs remain readable. |
| Medium | Instructions encouraged repetitive checking and described all spawned agents as starting with fresh context. Cache guidance omitted new model/client behavior. | Bounded verification, explicit stopping conditions and fresh-context selection, failure diagnosis before retry, and current model/cache sources. |
| Medium | Local `main` held completed compaction work absent from GitHub, while GitHub held newer token-accounting work. | Reconciled both histories in an isolated audit worktree; retained continuity tests and all existing token-accounting features. |
| Medium | A malformed checkpoint `evidence_paths` value could crash validation. | Return validation errors for malformed collections and reject boolean schema versions. |
| Low | Claude model selection offered floating aliases without current exact IDs. | Offer Fable 5.1, Opus 5, and Sonnet 5 IDs alongside aliases. Inherited model choice remains available. |
| Low | The UI's supplied environment selected one executable for availability but the process environment selected another for discovery and launch. | Carry the same runtime selection through real UI navigation, catalog discovery, and command construction; regression uses two executable fixtures. |

Four defects were independently reproduced by running the pre-change code in temporary fixtures: role overwrite, mixed workflow cost groups, non-finite costs, and rollback overwriting later edits. Permanent regressions exercise the corrected behavior. Scratch evidence is kept under ignored `.oas/audit/`.

## Adversarial review

The interaction reviewer reproduced the supplied-environment mismatch. The test-honesty reviewer reproduced the configuration-label collision through the actual logging/reporting CLI. Neither finding depended on the other. Both received focused fixes.

The data-loss reviewer found no new defect in the reviewed snapshot/rollback changes, but reproduced the preexisting automatic-recovery defect. The broader audit addressed it in a separate commit. The fresh verifier caught permission-only edits still being lost; both automatic recovery and explicit rollback now compare installed modes too. The installation regression exercises `setup.main --apply` with an injected write failure and eight cases: existing/created files changed to text, replaced by symlinks, removed, or made read-only before recovery. Untouched writes must still recover. Older manifests retain their documented byte-only comparison.

The three first-round regressions fail against a disposable copy of the pre-fix commit and pass after the fixes. A fresh reviewer independently repeated that comparison and inspected adjacent behavior. Permission-edit regressions also fail against the first fix and pass with mode checks. The legacy-manifest check verifies compatibility rather than claiming to expose a regression. No speculative findings were promoted to fixes, and no external issues were filed.

## Verification

- 163 unit tests passed on the local Mac under Python 3.11, 3.13, and 3.14, including all prior coverage, merged continuity coverage, and new regressions.
- `python3 scripts/oas.py check`, its optimized-Python variant, and `git diff --check` passed.
- Codex 0.154.0-alpha.6.2 from the desktop app advertised `gpt-6-astra`. Native startup showed Astra at `high` with the selected worker/retry role layers and no configuration error; the session was exited without a model request.
- Claude Code 2.1.266 started Fable 5.1 at `high` with auto mode enabled. Its normal updater advanced the installation to 2.1.272, which started Opus 5 at `high` with auto mode enabled. Both sessions showed zero model tokens and were exited.
- The installer tests cover preserved runtime selection, valid shell quoting, idempotence, collision checks, backups, rollback preservation, and concurrent-change refusal.

GitHub Actions did not execute its Python matrix: the service reported failed account payments or a spending limit. The same Python versions passed locally on macOS; those results do not establish Linux-hosted CI success. No billing settings or CI definitions were changed to bypass the failure.

The first Codex startup was blocked by the outer execution sandbox preventing writes to its local database. Startup succeeded with normal state-directory access; no database repair was necessary.

## Preserved boundaries and remaining limits

Profiles retain native permission mappings, three child slots, read-only tutoring, and no escalation in unattended mode. No global model is forced, no API gateway or inference router is added, and canonical skills remain in their own repository. The existing skill-directory drift check is advisory; a versioned catalog integration belongs to the coordinated skills work.

Native startup exposed inherited MCP authentication/configuration warnings. They are separate from this repository's settings and require account-specific follow-up; they were not hidden or disabled. Doctor also reports terminal and host-environment diagnostics, so a nonzero overall result is not automatically an OAS config failure.

Startup and schema validation do not prove inference quality, cost savings, live delegation, or compaction summary quality. Use matching versioned tasks and record actual outcomes before promoting a model/effort policy. Draft PR #5 remains separate; this audit used primary model documentation directly rather than adopting its unverified source reconstruction.
